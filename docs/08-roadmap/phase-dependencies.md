## قواعد هماهنگی 🔒

### قاعدهٔ ۱ — ترتیب اجباری
🔒 فاز N فقط پس از تکمیل کامل فاز N-1 (در مسیر بحرانی) شروع شود.

### قاعدهٔ ۲ — مرز ماژول
🔒 موتورها فقط از طریق سه درگاه ارتباط:
- `Container::make(Interface::class)` — pull-based DI
- `EventDispatcher::dispatch('event', $data)` — pub/sub
- `EngineBus::call('engine', 'action', $input)` — RPC

🔒 `use Tavaan\Engine\<Other>\...` مستقیم بین موتورها = ❌ ممنوع.

### قاعدهٔ ۳ — Contract-First
🔒 هر موتور قبل از پیاده‌سازی:
1. Interface در `core/Contracts/<Area>/` تعریف شود
2. پیاده‌سازی در `engines/<name>/src/` پشت قرارداد

### قاعدهٔ ۴ — تست هم‌زمان
🔒 هر موتور هم‌زمان با پیاده‌سازی:
1. Unit Tests (≥۹۰٪ پوشش کلاس‌های عمومی)
2. Feature Test (جریان اصلی)
3. Benchmark (با اهداف عددی)

### قاعدهٔ ۵ — مستند هم‌زمان
🔒 هر موتور هم‌زمان با پیاده‌سازی، مستند ۱۷بخشی (DOC-150) تکمیل کند.

### قاعدهٔ ۶ — بدون Circular Dependency
🔒 وابستگی دور بین موتورها = ❌ ممنوع.
اگر A به B وابسته است، B نباید به A وابسته باشد.

### قاعدهٔ ۷ — عمق وابستگی ≤ ۵
🔒 زنجیرهٔ وابستگی نباید بیشتر از ۵ عمق داشته باشد.
مثال مجاز: A → B → C → D → E (۵ عمق)
مثال ممنوع: A → B → C → D → E → F → G (۷ عمق)

### قاعدهٔ ۸ — شفافیت رابط
🔒 هر موتور Facade دارد با `@mixin` و `@method`.
🔒 Facade فقط accessor است، نه پیاده‌سازی.

## چک‌لیست تکمیل فاز

برای هر فاز قبل از شروع فاز بعدی:

- [ ] همهٔ موتورهای فاز، `engine.json` معتبر دارند
- [ ] همهٔ موتورها `ServiceProvider` فعال دارند
- [ ] همهٔ Interfaceها در `core/Contracts/` موجودند
- [ ] Unit Tests ≥۹۰٪ پوشش
- [ ] Feature Test برای جریان اصلی
- [ ] Benchmark با اهداف عددی
- [ ] مستند ۱۷بخشی کامل
- [ ] `declare(strict_types=1)` در همهٔ فایل‌ها
